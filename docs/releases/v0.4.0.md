# U-DSH Portable v0.4.0 — WebUI 版接入虾盘云设备钱包

这一版把 Electron 桌面版才有的**设备钱包**移植进了 WebUI 便携版：
**一键启动 → 自动领钱包 → 一键充值 → 直接对话**，不用注册、不用申请 Key、不用手动配置。

## 用户看到什么

1. 双击「启动 U-DSH Web」→ 首次启动自动向虾盘云领一把属于这台设备的密钥（`wal_…`），
   写入 DSH 配置，把「虾盘云」设为默认模型来源（模型清单走 `/v1/models` 动态拉，80+ 个）
2. 新钱包余额接近 0 → **自动打开充值页**（浏览器，微信/支付宝），充完回终端即可对话
3. 之后随时双击「钱包」看余额/复制密钥/换一把/填入已有 Key；双击「充值」直接开充值页

## 技术上怎么做的

| 点 | 说明 |
|---|---|
| 集成位置 | 启动器在**拉起 DSH 内核之前**收敛钱包，写完配置再启动；DSH 本身一行没改 |
| 状态存哪 | `data/u-dsh-state/device-wallet.json`（五字段：apiKey/walletId/pendingKey/pendingKind/pendingFrom），**跟着 U 盘走**，宿主机不留凭证 |
| 写配置 | `.credentials.yaml` + `settings.yaml` 都是「临时文件 → fsync → rename」原子写；两道配置不会出现半截态 |
| 断网/只读盘 | 一律不阻塞启动（契约 C1）：领不到就跳过，DSH 照常起，下次自愈 |
| 换 Key | 两阶段（mint → 只读验证 → commit），旧 Key 在 commit 前始终有效；余额记在钱包上不受影响 |
| 移除钱包 | 只清本机，不调用服务端删除、不清余额 |
| 面板 | 本地 `node:http` 单页，无外部依赖；含复制密钥、余额刷新、充值、换一把、填入已有、危险区移除 |

## 接的时候踩到两个真 bug（都已修）

| 现象 | 根因 | 修法 |
|---|---|---|
| 第二次启动内核直接退出，报 `unknown top-level key "XIAPAN_CLOUD_API_KEY"` | 我按老格式把 Key 写在 `.credentials.yaml` 顶层；DSH 0.2.x 的凭据文件是 `{version, refs:{…}, records:{}}` | 按文件自身 schema 写入；新建文件一律用现代 schema |
| 首装后内核起不来，报 `is readable beyond its owner (mode 644)` | 普通写文件是 644；DSH 要求凭据文件只有属主可读 | 凭据文件写完 `chmod 600`（软盘 exFAT 上是 700，所以之前没暴露） |

这两条都是真机跑出来的，单测和 CI 都没抓到——正好说明"真机验证脚本"的价值。

## 必须告诉你的一件事：新钱包余额是 **1 token**

实测 bind 出来的新钱包 `total_available: 1` —— 也就是说**客户第一次进来、发第一条消息必然失败**。
这不是 bug，是服务端策略。低价会审（4 个模型 + 裁判）把这条列为「首启转化的生死线」，给了三条路：

| 方案 | 做法 | 影响 |
|---|---|---|
| **A 免费试用额度**（推荐） | 服务端在 bind 时按设备/IP 限发一次 ¥1–2 等值额度（约 50 万–100 万 token） | 转化最好；要改服务端，且必须严格防刷 |
| **B 首启直接导流充值**（已实现） | 余额 ≤1 时自动打开充值页 | 现在就能用；但客户还没体验到价值就被要钱 |
| C 允许自备 Key | 面板里「填入已有 Key」 | 已支持，但这类用户不会给我们付费 |

现在实现的是 B（A 需要你决定并改服务端）。

## 会审还提了三条（没做，等你拍板）

1. **钱包找回**：U 盘丢了 = 余额找不到人。要么做恢复码，要么在文档里明说"密钥就是钱包、丢了不补"。
2. **凭据明文在盘上**：网咖/公司电脑插过的盘，Key 可被复制刷余额。缓解靠服务端限额+一键吊销，客户端加密与"便携"天然冲突。
3. **价格展示**：面板目前只显示余额，不显示单价。`/api/pricing` 有数据就显示，没有就空着（不估、不写死）。
