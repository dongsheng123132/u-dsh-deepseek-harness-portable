# U-DSH Portable v0.3.0 — 引擎装本机、资料随盘走

这一版换了骨架：**U 盘只带你的东西，引擎装到电脑本机。**

- U 盘上：`data/dsh-home`（Key、会话、工作区、钱包状态）+ 一个引擎归档
- 客户电脑上：Node 运行时 + DSH 闭包（首次启动解一次，之后从本机高速启动）

换电脑不用重装、不用重新登录：插到另一台电脑，首次自动解一次引擎（8–10 秒），资料还是盘里那份。

## 引擎放哪：`UDSH_ENGINE_MODE`

| 模式 | 引擎在哪 | 什么时候用 |
|---|---|---|
| `auto`（默认） | 本机；移动硬盘 ≥128 GB 时装盘上 | 大多数 U 盘 |
| `host` | `%LOCALAPPDATA%\U-DSH\engine\<版本>` / `~/Library/Caches/U-DSH/engine/<版本>` | 强制装本机 |
| `drive` | `<盘根>/engine/<版本>` | 移动硬盘 / SSD，自包含 |
| `temp` | 系统临时目录，退出清理 | 对"装到本机"敏感的客户，零残留 |
| `usb` | 不安装，直接从盘跑 | 最慢、零残留（单文件归档形态下自动退化成 `temp`） |

版本按 DSH 包版本隔离 + 原子落地：升级不会碰旧目录，可回退；第二次启动直接复用。

## 盘上只有一个大文件：`engine.tar.gz`

把 1.2 万个文件的引擎闭包直接铺在 exFAT 盘上，实测很惨：

| | 旧的松散目录形态 | 现在的单文件归档 |
|---|---|---|
| 盘上文件数 | 12,057 | **21** |
| 盘上占用 | 1.4 GB | **234 MB** |
| 拷进 U 盘 | ~40 分钟 | **78 秒** |
| 首次启动 | 从 U 盘 copy 12,057 个文件到本机 | 本机原地解包 **8–10 秒** |

exFAT 常见 128 KB 簇，4 KB 的文件也占一格，小文件一多就两头都慢。现在 Node 不在 U 盘上跑，
引擎解到客户电脑本机，U 盘只负责带数据 —— 这样做只为了**快**，也顺带让 U 盘更轻。

首次启动会在终端里说明"正在把引擎装到这台电脑"，客户看到进度不用慌。

## 实测（macOS + exFAT 卷，本轮）

| 用例 | 结果 |
|---|---|
| 陌生电脑首次启动（`auto` → 装本机） | 8/8 ✅ 解包 8.1–9.2 s，本机引擎 446 MB，HTTP 首页 200 |
| 第二次启动 | 8/8 ✅ 复用，不再解包 |
| `temp` 模式 | 4/4 ✅ 退出后临时目录零残留 |
| `drive` 模式（装盘上） | 7/7 ✅ 解到 `<盘根>/engine/0.2.0-rc.2` |
| 换一台电脑（删掉本机引擎后重跑） | ✅ 自动重解 7.8 s，盘上数据（profiles/sessions/标记文件）原样还在 |
| 真启动器双击（`启动 U-DSH Web.command`） | ✅ 引擎 host + 数据在盘 + 自动开浏览器 |

## 已知

- **Windows 端**：同一套代码，本轮的端到端真机验证还没跑（需要能连 pc-3116 的控制端 token）。
  CI 在 `windows-latest` 上跑 `npm test`，引擎安装逻辑的单测覆盖 Windows 路径；但"打包成品在真
  Windows + 真 U 盘上首装"这一层还没验。**验证通过前，Windows 用户建议继续用 v0.2.1**。
- 本轮测试机上的那支 exFAT U 盘**有坏块**：同一个 115 MB 文件连考两次校验和都不同，
  16 MB 分片 8 个里坏 1 个。exFAT 卷本身的一致性另测过（32 KB 簇镜像卷），上面的用例都在那个卷上跑。
  怀疑是这支盘本身的问题，建议换盘或整盘重格式化后再用。
- Electron 桌面版的 `kernel-manager.js` 还是旧逻辑（从盘上直接跑），下一版改。
