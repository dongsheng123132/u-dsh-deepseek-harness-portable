# U-DSH Portable v0.2.0

> **预发布（pre-release）。** 内核随包这条主线已在干净机上验真，
> 但首次运行体验的修复只有本机与单元测试证据，**尚未在真实 U 盘 + 真机上复验**。
> 所以标 pre-release 而不是正式版 —— 已知问题在文末如实列出，请先看一眼再用。
>
> `## 已验证` 一节只记真跑过的东西，没跑过的不写。

架构级变更：**内核不再在客户机上安装，改为构建时随包 vendor**。
版本号从 0.1.x 跳到 0.2.0 就是因为这个 —— 包的性质变了，不该复用补丁号。

## 追记（2026-08-24）：SFX 资产重建，转正式版

首发的 `.exe` 有打包缺陷：`build-sfx.mjs` 用 `7z -xr!data` 排除运行期 `data/`，
但 7z 的排除规则按条目名不分深度匹配，把内核里 4 处必须发布的 `data` 目录
（`pi-ai/dist/providers/data/`、两处 `protobufjs/*/tests/data/`、`node-gyp/gyp/data/`，
共 43 个文件）一并排除了。后果：内核插件加载必现
`ERR_MODULE_NOT_FOUND ... amazon-bedrock.json`，用户看到「U-DSH Portable 启动失败」。
zip 载荷由 electron-builder 打包，从未受影响。

修复：`build-sfx.mjs`（c2e18ee）改为 cwd=unpacked 内显式列出顶层条目打包，
不再用任何按名字匹配的排除规则。新 exe 已重传同名资产
（MD5 `c40589f1318dc9f5363f94475a157ef9`），并在真实客户机
（Windows 11 + USB 硬盘 NTFS）全链路复验：解压 34988 文件 → 启动就绪 →
内核 HTTP 200 → deepseek-v4-pro 真实对话回话成功。据此 v0.2.0 从 pre-release 转正。

经验：SFX 与 zip 并存时两者内容会分叉，「发布前 diff 两个包的条目清单」
应当进发布检查单。

## 变更

### 内核随包，客户机零 npm

构建时把 Node 运行时和 `@deepseek-ai/dsh` 的完整依赖闭包装进
`resources/runtime/` 与 `resources/harness/`。客户机不装 Node、不跑 npm、不下载内核。

`src/kernel-manager.js` 从 557 行降到 149 行 —— `installDsh`、`discoverSystemDsh`、
`discoverSystemNode`、下载解压那一整套全部删除，`ensure()` 变成毫秒级纯本地校验。

这一步同时消灭了 v0.1.x 时代反复出现的一整类故障：npm 镜像 `ETARGET`、
`--before` 时间窗、peer 依赖不收敛、4 分钟安装超时、客户机没网就废，
以及「复用到本机一个装坏的全局 DSH」引发的连锁失败。

代价：zip 从 139MB 涨到约 234MB；**首次解压很慢**（见下方已知问题）。

### 首次运行体验

- 启动前真探一次数据盘能否建 junction，exFAT/FAT32 直接给「请转成 NTFS」，
  不再让用户撞裸 `EISDIR`
- 启动失败翻成人话：`ENOSPC` / `EADDRINUSE` / `EPERM` / `EISDIR` 各有一句说明
  和一个能照做的动作，原始信息保留在详情里
- **落盘日志**：`paths.logsDir` 此前有零个消费者，钱包签发失败只写一句
  `console.warn` 就静默降级，而打包后 GUI 没有控制台 —— 失败在磁盘上不留任何痕迹。
  现在有了，失败弹框也会附上日志路径
- 钱包未就绪（没签发 / 换 Key 没走完 / 余额为 0）时主动把钱包页递到用户面前，
  不让人一路走到对话框才撞 `API key is invalid`
- DSH 界面右上角常驻钱包入口

### 许可合规

- 覆盖全部 528 个随包组件的许可清单（`third-party-licenses/NOTICES.md` 1.4MB
  + `manifest.json`），带会失败的门禁 `npm run licenses:check`
- 剪掉 `@img/sharp-wasm32`（8.7MB，Windows 用不到，且是 LGPL）
- 保留的 `@img/sharp-win32-x64` 含 libvips（LGPL-3.0-or-later），
  以两个可替换的独立 DLL 形式分发，`NOTICE.md` 有专门段落说明替换方式
- `LICENSE` 补本项目版权行；README 增加商标声明

### 自解压 exe：解压快一个数量级，体积还更小

`Expand-Archive`（= 资源管理器「全部解压缩」）在 34987 个文件上慢得离谱。
同机同包实测：

| 方式 | 耗时 | 下载体积 |
|---|---|---|
| zip + `Expand-Archive` | **580 秒** | 231.3MB |
| **7z SFX 自解压 exe** | **61 秒** | **142.4MB** |

快 9.5 倍，还小 39%（LZMA2 比 zip 的 deflate 压得狠）。干净云主机上
Expand-Archive 实测 1233 秒，按此比例可降到约 2 分钟。SFX 自带进度窗口，
不再是干等无反馈。

两种产物**并存**：`.exe` 给普通用户，`.zip` 给会用解压工具的人和自动化。

`scripts/build-sfx.mjs` 里带一道安全门禁：便携软件的数据目录就在 exe 旁边，
只要从 `win-unpacked` 启动过一次（冒烟测试就会）`data/` 就会长出来 ——
带真钱包跑过的话设备 Key 就在里面。打包时整个排除 `data/`，
且发现疑似凭据直接拒绝打包。

### 防误发

- `dist:mac` / `dist:linux` 被门禁挡住 —— vendor 只产出 win32-x64，
  不拦就会打出「构建成功但缺内核」的坏包
- `dist:portable` / `dist:win` 链里加 `vendor:check`，没有闭包就打不出包
- `npm test` 先跑 `action-parity:check-generated` —— 此前动作清单漂移时
  测试照样全绿，属于假绿
