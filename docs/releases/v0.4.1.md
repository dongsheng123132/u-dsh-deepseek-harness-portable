# U-DSH Portable v0.4.1 — 口径校准 + 实测数据 + Electron 凭据修复

这一版不新增功能，做三件收尾的事。

## 一、实测数据（真 U 盘 `/Volumes/Xiapan`，macOS，DSH 0.2.0-rc.2）

| 场景 | 耗时 |
|---|---|
| 二次启动（引擎在本机缓存 + 数据已初始化——客户日常） | **6.1 s / 11.0 s** |
| 首装（本机无引擎：校验 0.9 s + 解包 14.7 s + 启动） | **26.2 s** |
| 首装里的解包本身 | 13.4–15.8 s（123 MB 归档 → 510 MB 引擎） |
| 空转 90 秒对 U 盘的写入 | 224 KB |
| 运行中内核打开的 U 盘文件 | 17 个，全部在 `data/dsh-home` |

结论：**启动时间不是靠"引擎放哪"决定的**。DSH 内核自己在 6–11 秒量级；引擎装本机真正买到的是
①拷盘/交付时间（1.2 万小文件 40 分钟 → 单归档 26 秒解压）
②慢 U 盘的启动与运行随机读
③U 盘磨损与换机体验（换机自动重解，数据不动）。

## 二、口径再校准

以前说"引擎装本机"，更准确的说法是：

> **数据随盘走，引擎只是可重建的本机缓存。**

- 客户资产 = `data/dsh-home`（配置/会话/Key/钱包）+ `data/u-dsh-state/`（钱包状态）
- 引擎 = `~/Library/Caches/U-DSH/engine/<版本>` 或 `%LOCALAPPDATA%\U-DSH\engine\<版本>`，**删了不影响数据**，下次启动自动重解
- 新增 `npm run engine:list` / `npm run engine:clear`（或 `node scripts/clear-engine.mjs`）看占用/清缓存

## 三、Electron 版同一个凭据 bug 修掉了

WebUI 版在真机上撞到的两个崩溃，Electron 版（`src/dsh-config.js`）同样存在：

| bug | 修法 |
|---|---|
| 把 Key 写在 `.credentials.yaml` **顶层**，DSH 0.2.x 判为 `unknown top-level key` 并拒绝启动 | 按文件自身 schema 写：新文件用 `{version, refs:{…}, records:{}}`，老平铺文件保持原样 |
| 凭据文件权限过宽（DSH 要求属主可读） | 写文件时 `mode 0o600`（Electron 侧本来就有），并新增回归测试 |

单测：`test/dsh-config.test.js` 3/3 通过（含"老格式不被改成新格式"的用例）。
