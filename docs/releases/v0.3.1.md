# U-DSH Portable v0.3.1 — 引擎装本机的加固版

v0.3.0 把架构换成了「重的东西装客户电脑、数据留 U 盘」。这一版是配套的**可靠性加固**，
把实测里真踩到的坑一个个堵上。

## 加固了什么

| 加固 | 为什么 |
|---|---|
| **归档 SHA-256 校验** | U 盘掉数据是真事：测试时同一个 115 MB 文件连拷两次，校验和都不一样。现在构建期把 sha256 写进 `engine.json`，首装前流式校验；坏了直接说「请把 U 盘上的 u-dsh 目录重新完整拷贝一遍」，而不是解到一半报诡异错误 |
| **本机空间预检** | 引擎解开约 450 MB。剩余空间 < 700 MB 时直接说清楚，不留给客户一堆 `ENOSPC` |
| **安装互斥锁** | 双击两次、或同一台电脑插两支 U 盘时，只有一个进程装，另一个等或直接复用；僵死锁 3 分钟超时自动清 |
| **temp 模式补扫** | Windows 的 `SIGTERM` 捕获不到，强杀时退出钩子不跑。改成「退出即清 + 下次启动扫掉 2 小时前的遗留临时引擎」 |
| **中文启动器名不乱码** | `Compress-Archive` 按 OEM 码页写文件名，解压后「启动 U-DSH Web.bat」变乱码。改用 .NET `ZipFile` / bsdtar，条目带 UTF-8 标志 |
| **包里不留 Node 的 npm 树** | Windows 运行时根下的 `node_modules/` 让包内条目从 11 涨到 2042。裁掉后 Windows 包 = **11 个文件**，mac 包 = **17 个** |
| **闭包用锁文件装** | DSH 内部包不是同批发布的，`--before` 时间窗太窄会 `ETARGET`；改用 `config/webui-closure` 锁文件 `npm ci`，确定性安装 |

## 实测（本轮新增的边界场景）

同一台电脑 / 换电脑 / 版本混杂，逐个跑过：

| 场景 | 结果 |
|---|---|
| 第二次启动 | 复用，不再解包（8/8） |
| 主机已有旧版本目录 | 装新版本到自己的目录，旧的原样保留 ✅ |
| 目标版本目录损坏（缺 manifest） | 检测到不完整，重新解包 ✅ |
| 降级（主机上有更高版本） | 只装 U 盘这一版，更高版本目录不动 ✅ |
| 双击两次（并发） | 两个进程都成功，无残留 staging ✅ |
| 归档被改坏一个字节 | 明确报「已损坏，请重新完整拷贝」✅ |
| 首装（auto→host，exFAT 卷） | 校验 0.1 s + 解包 15.8 s，8/8 ✅ |
| Windows（GitHub Actions `windows-2022` 真机） | 打包 → 首装 → 复用 → temp 零残留，全绿 |

## 下载

| 平台 | 文件 |
|---|---|
| macOS | `U-DSH-WebUI-Portable-0.3.1-mac.zip` |
| Windows | `U-DSH-WebUI-Portable-0.3.1-win.zip` |

盘上就十几二十个文件（一个引擎归档 + 精简 Node 运行时 + 启动器），拷进 U 盘是顺序读写，
首次启动在本机原地解包（8–16 秒），之后秒级复用。

## 仍然没做的

- **Windows 真 U 盘 + 真人双击**这一层还没跑（远程机 pc-3116 需要控制端 token）。
  CI 的 windows-2022 已经覆盖到「打包 → 首装 `%LOCALAPPDATA%` → 复用 → temp 清理」。
- Electron 桌面版（`kernel-manager.js`）仍是旧逻辑，下一版改成同一套引擎安装。
